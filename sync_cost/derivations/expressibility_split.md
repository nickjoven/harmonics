# Expressibility split — the lambda / EML divide

A methodological orientation document, parallel to `comparison_class.md`
(which fixes the framework's peer group) and `unitless_check.md` (which
fixes its unit-invariance commitment). This document fixes the
framework's *notational invariance*: the claim that no single universal
generator suffices to express the framework's content, and that the
discrete and continuous halves of physics require structurally
different formal languages.

## The opening intuition: bowed string vs. flute

A violin's pitch is `f = (n / 2L) · √(T/μ)` — a positive integer `n`
times a structural constant. The integer comes from counting half-
wavelengths fitting along the string; the structural constant comes
from the string's mechanical properties (tension, density, length).

A flute's pitch is `f = (n / 2L) · c_medium` — the same integer `n`
times a medium-dependent constant (the speed of sound in the gas
filling the tube).

The integer `n` is the same algebra in both cases: discrete counting
on a fixed combinatorial structure (the standing-wave mode lattice).
The dimensional anchor is different algebra in each case: continuous
function of mechanical properties for the string, continuous function
of medium properties for the flute.

**One of these algebras can be expressed in EML; the other cannot.**

That's the split this document formalizes.

## The two universal generators

The framework's content can be expressed cleanly in two distinct
languages, each of which is universal for one half of mathematics:

### EML (continuous, transcendental)

The operation `eml(x, y) = exp(x) − ln(y)` plus the constant `1` is
universal for elementary continuous mathematics. Every elementary
function (sin, cos, log, exp, +, ×, ÷) and every elementary
transcendental constant (e, π, i) can be built from `eml` and `1`
alone. This is a Sheffer-stroke result for the algebra of continuous
elementary functions: EML is to that algebra what NAND is to Boolean
logic.

Internal structure of EML: separable in its arguments
(`f(x, y) = exp(x) − ln(y)`), strictly convex in each, with no
critical points; the canonical bridge between the additive group
`(ℝ, +)` and the multiplicative group `(ℝ⁺, ×)`.

### Mediant (discrete, combinatorial)

The operation `(a+c)/(b+d)` on positive rationals plus the boundary
endpoints `0/1` and `1/0` is universal for the positive rationals.
Every positive rational appears exactly once in the Stern-Brocot tree
generated by iterating the mediant. This is a structural-generator
result: the mediant is to `ℚ⁺` what the successor function is to `ℕ`.

Internal structure: column-summing on 2×2 unimodular matrices,
generates `SL(2, ℤ)`, continuum closure `SL(2, ℝ)` is 3-dimensional
(this is where the framework's `d = 3` comes from).

## What each generator can express

| Framework element | EML-native? | Mediant-native? |
|---|---|---|
| Saddle-node passage time `τ ~ 1/√ε` | yes (one call) | no |
| Born-rule angular spread `Δθ ~ √ε` | yes (one call) | no |
| Uncertainty product `τ · Δθ = 1` | yes (`eml(0, 1)`) | no |
| Boltzmann weight `e^{−βE}` | yes (one call) | no |
| Partition function `Z = Σ e^{−βE_i}` | yes (sum of EML calls) | no |
| Free energy `F = −kT ln Z` | yes (two calls) | no |
| Tongue width `(K/2)^q` (`q` known) | yes (one call) | uses `q` integer |
| Born rule `|ψ_i|^2 = e^{−βE_i}/Z` | yes (two calls + arithmetic) | no |
| Mediant `(a+c)/(b+d)` | requires bootstrap | one operation |
| Stern-Brocot tree | not natively (no recursion) | one definition |
| Farey count `|F_n| = 1 + Σ φ(k)` | not natively (no enumeration) | clean recursion |
| `Ω_Λ = 13/19` | yes via integer bootstrap, depth ≈ 10 | direct, depth 1 |
| `sin²θ_W = 8/35` | yes via bootstrap, depth ≈ 10 | direct, depth 1 |
| `α_s/α_2 = 27/8` | yes via bootstrap, depth ≈ 10 | direct, depth 1 |
| `n_s ≈ 0.965` (involves `log φ²`) | yes (one EML call given log of constant) | not natively |
| `K_c = 2/π` | involves `π` (EML can build) | not natively |
| Spatial dimension `d = 3` | not native (it's an integer) | structural — `dim SL(2, ℝ)` |
| Three generations of fermions | not native | counting at `q ∈ {2, 3}` |
| Charge quantization | not native | `S¹` compactness, mediant primitive |
| Klein-bottle XOR mode count = 4 | not native | discrete topology |

The pattern: **EML is good at the dynamics; mediant is good at the
structure.** Each can in principle express the other's content, but
only at the cost of depth-blowing nested expressions or external
recursion machinery.

## What this means for the framework's four primitives

The framework's four primitives (D10) split cleanly across the
expressibility line:

| Primitive | Native generator | What it does |
|---|---|---|
| Integers | mediant-side | counting |
| Mediant | mediant-side | combining |
| Parabola | EML-side | normal form near saddle nodes |
| Fixed-point | bridges both, requires Y-combinator | iteration / self-reference |

The fixed-point primitive is the only one that straddles. Iteration
is *not natively expressible in either generator alone*; it requires
a recursion device (Y combinator in lambda calculus, recursion in
Haskell or Python). The framework's bet is that iteration sits above
both generators because it is what makes the universe *compute*
rather than merely *describe*.

## The broader claim

The Sheffer-stroke universality of NAND for Boolean logic, of EML for
continuous elementary mathematics, and of the mediant for the positive
rationals are three instances of the same pattern: each algebra has
*its own* minimal universal generator. There is no single universal
generator across algebras. **Physics, the framework asserts, requires
both the continuous-algebra Sheffer stroke (EML) and the discrete-
algebra Sheffer stroke (mediant), because physics has both kinds of
content.**

The Standard Model implicitly assumes one Sheffer-stroke is enough —
it expresses everything in a single QFT-style continuous algebra and
takes its discrete content (integer charges, three generations,
spatial dimension `d = 3`) as boundary conditions rather than derived
output. This framework rejects that compression: discrete combinatorial
content requires its own generator and cannot be reduced to the
continuous one without depth blowup.

This is why the framework has *four* primitives and not one. EML
covers the parabola primitive; mediant covers the integer and
mediant primitives; fixed-point bridges them. No simpler decomposition
exists.

## The empirical posture this implies

For any given framework prediction, ask first:

- **Is it discrete or continuous?** Discrete predictions are mediant-
  native and read most cleanly as exact small-integer ratios. Continuous
  predictions are EML-native and read most cleanly as transcendental
  evaluations.
- **Which generator is doing the work?** This identifies which kind of
  invariance the prediction has. Mediant-side predictions are
  topologically invariant (they don't change under medium swap or
  unit choice). EML-side predictions are scale-invariant up to the
  dimensional anchor.
- **Is the prediction symbolic-regression accessible?** If the
  prediction is mediant-side, it cannot be discovered by symbolic
  regression on EML-only expressions; an external counting structure
  must be supplied. If EML-side, it can in principle be rediscovered
  by symbolic regression on raw data.

This last bullet is the falsifiability handle the EML community
provides for the framework. If symbolic regression on cosmological
data, restricted to EML-only expressions, *fails* to find `Ω_Λ = 13/19`
as the minimum-complexity description, that confirms the prediction
is genuinely mediant-side rather than a coincidence. If it
*succeeds*, the framework has a distinct empirical signal worth
investigating further.

## Practical consequence for the repo

The framework's structural derivations live in `framework_core.py`
and `framework_core.hs`. Both are pure-functional; both use the
mediant operation natively. EML-side content (saddle-node passages,
partition functions, tongue widths) appears throughout
`derivations/*.py` in conventional notation. The repo does not
attempt to translate either side into the other; the split is honest
about which generator is doing the work where.

For pedagogy, the bowed-string-vs-flute analogy from
[`medium_change_demo.md`](medium_change_demo.md) is the clearest
physical instance of this divide and the recommended opener.
