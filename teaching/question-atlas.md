# Question atlas for Harmonics

This file treats the teaching deck as a set of askable moves.

The unit is not a card, lesson, hand, or document. The unit is a
question that can open a piece of the framework without forcing a
premature answer.

Scope: complete v0 for the repository entry points, mastery graph,
derivation atlas, scorecard, status discipline, demos, and declined
claims. It should be extended when the repo adds new canonical claims or
changes status.

Source hierarchy for claim questions:

1. `MANIFEST.yml`
2. `sync_cost/derivations/framework_status.md`
3. `sync_cost/derivations/statistical_conventions.md`
4. `sync_cost/derivations/phenomenology_cross_reference.md`
5. `sync_cost/derivations/structural_lemmas.md`
6. individual derivation files

## How to Use This

Each question can become a card, a video beat, a discussion prompt, a
demo task, or a review question. Most questions should be asked before
their framework answer is shown.

Question types:

- **Entry**: opens curiosity.
- **Model**: asks the learner to manipulate a picture, knob, or toy
  system.
- **Bridge**: connects ordinary language to standard physics/math.
- **Derivation**: asks what follows from what.
- **Status**: asks what is claimed, anchored, declined, or open.
- **Falsifier**: asks what would break the claim.
- **Transfer**: asks the learner to apply the structure elsewhere.

## Maintenance Rule

When the repo changes, add questions before adding answers. A new claim
should first appear as:

1. What is being asked?
2. What would count as a structural answer?
3. What would count as an anchor-side answer?
4. What would demote it to Class 2?
5. What would falsify it?

The deck stays honest if the question space stays richer than the answer
space.
